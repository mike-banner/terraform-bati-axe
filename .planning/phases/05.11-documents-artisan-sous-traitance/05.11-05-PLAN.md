# Plan 05.11-05 — Fusion `documents_artisan` → `verifications` + verrou sous-traitance

**Statut : GO donné le 2026-11-06 — T1 à T9 faites en local, reste le push cloud (voir SUMMARY).** Décision de Mike du 2026-11-05 : option A (fusion dans `verifications`).
Source : spécification client « Appels d'offres publics » (`ROADMAP.md` sous 05.11) — la plateforme bloque la capacité de sous-traitance tant que les pièces obligatoires ne sont pas validées.

## Pourquoi

Constats vérifiés le 2026-11-05 (code + base cloud) :
- Aucun code n'insère dans `documents_artisan` ; table cloud = 0 ligne. `verifications` (0 ligne, 2 pros) est le seul modèle alimenté par un flux d'upload réel, avec triggers de garde et RLS lecture seule (ADR-012).
- `me.patch.ts` accepte `is_available_subcontracting` sans aucun contrôle de pièces.
- **Bug découvert** : `server/api/v1/cron/decennale-alerts.get.ts` (alertes J-30/J-7, 06.3-02) lit `documents_artisan` → les alertes décennale ne partent jamais pour personne.
- La sélection DirCo (05.10) ne lit pas `documents_artisan`.

## Décisions de conception (à confirmer au « GO »)

Pièces : Kbis approuvé ≤ 3 mois, décennale approuvée non échue, URSSAF approuvée non échue, RGE valide si le pro a un métier énergie | une seule source de vérité TS |
