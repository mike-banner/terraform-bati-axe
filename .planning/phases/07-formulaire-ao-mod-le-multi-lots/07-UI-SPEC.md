# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Scope note (read first)

This phase is a **form extension**, not a new UI surface. It adds 4 fields to
2 existing screens:

1. `app/pages/b2b/partenaires.vue` (public tunnel, step 3) — description
   (obligatoire), sélecteur multi-lots (syndic uniquement).
2. `app/components/admin/AdminB2bTab.vue` (qualification DirCo) — statut
   confirmé/en attente, code postal structuré.

No new page, no new component, no new design pattern. Every field below
must be styled with the **exact Tailwind utility classes already used in
the file it's added to** — copy the nearest existing sibling field
(`<input>`, `<select>`, pill-toggle button) and change only the label,
`v-model`, and validation. Do not introduce shadcn `<Select>`/`<Input>`
components into these two files just because `components.json` exists —
neither file currently uses shadcn primitives (both hand-roll native HTML
inputs with Tailwind), and mixing the two styling systems inside one form
would be a worse outcome than staying consistent with the surrounding code.

## Spacing Scale

Declared values (must be multiples of 4), matching `--space-*` tokens already in `app/assets/css/tailwind.css`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps |
| sm | 8px | Gap between pill-toggle buttons (`gap-2`), label-to-input (`mb-1.5` ≈ 6px, existing convention — keep as-is) |
| md | 16px | Between stacked form fields (`mb-4`, `space-y-4`) |
| lg | 24px | Block-to-block within a step (`mb-6`) |
| xl | 32px | n/a in this phase (no new page-level sections) |

Exceptions: existing codebase uses `mb-1.5` (6px) between label and input universally in both target files — this is a pre-existing exception to the 8px grid, not introduced by this phase. Keep it for consistency rather than "fixing" it to `mb-2`.

## Color

Two distinct accent tokens are already established per-surface. This phase does **not** unify them — that would be an unrelated design-system change outside this phase's boundary (per CONTEXT.md scope).

### Public tunnel (`app/pages/b2b/partenaires.vue`)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (`--color-background`) | Page/card background |
| Secondary (30%) | `#E2E8F0` (`--color-border`), `#F8FAFC`-ish muted | Input borders, card borders, muted backgrounds |
| Accent (10%) | `#C2410C` (`--color-copper`) | Selected pill/card state (`border-copper bg-copper/5 ring-copper/20`), selected corps-de-métier pill (reuse `TRAVAUX_OPTIONS` pattern exactly: `border-copper bg-copper/10 text-copper`), submit/continue CTA (`bg-copper text-white`) |
| Destructive | `#DC2626` (`--color-border-error` family, `text-destructive`) | Description-too-short validation error only |

### Admin qualification (`app/components/admin/AdminB2bTab.vue`)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` / `--color-background` | Card body |
| Secondary (30%) | `#E2E8F0` border, `bg-muted/50` | Field borders, hover rows |
| Accent (10%) | `#EA580C` (`--color-safety`) | Focus ring on new inputs (`focus:border-safety`, matches every existing input in this file), "Enregistrer" button stays `bg-safety` — new status `<select>` and postal code `<input>` must use the **same** `focus:outline-none focus:border-safety` pattern as `qualifications`/`planning_start` inputs, not copper |
| Destructive | `#DC2626` | Postal code format error only (regex mismatch) |

Accent reserved for: selection state (tunnel) / focus state (admin) and primary CTA — never for plain body text or borders of unselected/default fields.

## Component-Level Notes (for planner/executor)

**Multi-lots picker (syndic, tunnel step 3):** reuse the `TRAVAUX_OPTIONS` toggle-pill pattern verbatim (`app/pages/b2b/partenaires.vue` lines ~303-319, the diagnostiqueur "Travaux suggérés" block) — same button classes (`px-3 py-1.5 rounded-full border text-xs font-medium`, selected = `border-copper bg-copper/10 text-copper`, unselected = `border-border text-muted-foreground hover:border-muted-foreground/50`), same `toggleX()` array-splice helper pattern as `toggleTravail()`. Source the checklist options from the existing category vocabulary used elsewhere in the codebase (`professionals.categories` — planner to confirm exact list; this is a data question, not a visual one).

**Status selector (admin):** reuse the exact `<select>` markup already used for "Statut pipeline" in the same component (`w-full h-9 px-2.5 text-sm rounded-sm border border-border bg-background text-foreground focus:outline-none focus:border-safety`), just a second `<select>` with 2 options instead of 6.

**Postal code input (admin):** reuse the exact `<input>` markup already used for `planning_start`/`planning_end` (`w-full h-9 px-2.5 text-sm rounded-sm border border-border bg-background text-foreground focus:outline-none focus:border-safety`), `type="text"` with `maxlength="5"` and `pattern="\d{5}"` (HTML constraint mirroring the Zod `^\d{5}$` server rule per CLAUDE.md input-validation rule).

**Description textarea (tunnel):** no textarea currently exists in `partenaires.vue` — borrow the textarea styling from `AdminB2bTab.vue`'s "Notes internes" block instead (`w-full px-2.5 py-2 text-sm rounded-sm border ... resize-y`) but swap `border-border`/`focus:border-safety` for the tunnel's own input classes (`border-border rounded-sm ... focus:ring-2 focus:ring-ring`, matching the sibling `<input>` fields in the same step) — do not mix admin's `focus:border-safety` into the public tunnel.
