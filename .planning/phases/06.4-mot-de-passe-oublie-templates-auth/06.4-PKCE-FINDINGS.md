# 06.4 — Format réel du lien de réinitialisation (mesuré le 2026-10-30)

Mesure sur Supabase local (GoTrue, SMTP Resend coupé le temps du test pour capturer l'e-mail dans Mailpit), parcours réel depuis `/pro/claim`.

- E-mail : sujet « Reset Your Password » (modèle Supabase par défaut, templates brandés 06.4-01 non posés).
- Lien : `<API>/auth/v1/verify?token=…&type=recovery&redirect_to=<site>/pro/reinitialiser-mot-de-passe`
- Arrivée : `<site>/pro/reinitialiser-mot-de-passe?code=…` → **flux PKCE** (query `?code=`), pas de `#access_token`.
- Résultat : formulaire affiché, nouveau mot de passe accepté (connexion 200), ancien refusé (400), redirection vers `/pro/claim`, lien réutilisé → « Ce lien n'est plus valide ».

À noter :
- Un lien produit par l'API admin `generate_link` arrive au format implicite (`#access_token`) : la page ne le traite pas (le client est en PKCE). Sans impact sur le flux réel, ne pas s'en servir pour tester.
- Le `redirect_to` n'est honoré que s'il figure dans les Redirect URLs (local : `config.toml` ; dev/prod : Dashboard Supabase), sinon GoTrue renvoie vers le Site URL.
- Le SMTP local pointe sur Resend (`[auth.email.smtp] enabled = true`) : en local, les e-mails Auth ne passent pas par Mailpit.
