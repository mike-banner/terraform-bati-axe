# Contexte — Phase 06.4 : Mot de passe oublié (pro) & Templates Auth Supabase

Créée le 2026-08-30, en aval de l'audit email de la Phase 06.3. Rattachée à
la Phase 6 (comme 06.1/06.2/06.3) — même famille « notifications/auth ».

## Constat (audit du 2026-08-30)

- **Aucun flux "mot de passe oublié" n'existe** : `app/pages/pro/claim.vue`
  a un login (`supabase.auth.signInWithPassword`) mais aucun lien de
  récupération. Un pro qui se trompe voit juste "E-mail ou mot de passe
  incorrect" — sans recours, doit contacter le support.
- Le seul mécanisme de reset existant est `supabase/scripts/reset-admin.mjs`,
  un script CLI manuel service-role, pour le compte admin générique
  uniquement (`auth.admin.updateUserById`) — rien côté self-service.
- Les templates d'e-mails Auth natifs Supabase (confirmation, recovery,
  invite, magic_link, email_change, etc.) sont actuellement les templates
  Supabase par défaut, non brandés BÂTI-AXE.
- Le SMTP Auth (Resend, `smtp.resend.com`) vient d'être branché en 06.3 —
  ce chantier devient utilisable maintenant que le volume n'est plus
  plafonné à 2/h.

## Périmètre proposé

### 1. Flux self-service pro
- Lien "Mot de passe oublié ?" sur `/pro/claim` (formulaire de connexion).
- Appel `supabase.auth.resetPasswordForEmail(email, { redirectTo })`.
- Nouvelle page (ex. `/pro/reinitialiser-mot-de-passe`) qui lit le token de
  récupération dans l'URL (session recovery Supabase) et appelle
  `supabase.auth.updateUser({ password })`.
- Gérer l'expiration du lien (`otp_expiry`, actuellement 3600s) proprement
  côté UI.

### 2. Templates Auth Supabase brandés
- `[auth.email.template.recovery]`, `.invite`, `.confirmation`,
  `.email_change` dans `supabase/config.toml` + fichiers HTML sous
  `supabase/templates/` — même branding copper/navy + footer LCEN que
  `server/utils/emailLayout.ts` (06.3-01), mais dans le format de template
  Supabase (variables `{{ .ConfirmationURL }}`, `{{ .Token }}`, etc., pas
  de logique JS).
- Configuration équivalente à poser dans le dashboard Supabase prod
  (Authentication → Email Templates) — ces fichiers locaux ne s'appliquent
  qu'à l'instance locale, le prod se configure séparément.

## Dépendances

- Phase 06.3 (moteur email, branding copper/navy, footer LCEN déjà définis
  dans `server/utils/emailLayout.ts` — réutiliser la palette, pas le code
  qui est côté app pas côté Supabase).
- SMTP Auth Resend déjà branché (06.3, `supabase/config.toml`
  `[auth.email.smtp]`).

## Hors périmètre

- Changement de mot de passe pour un utilisateur déjà connecté (paramètres
  de compte) — pas demandé, à ajouter si besoin plus tard.
- Flux équivalent pour l'admin — le script CLI existant suffit pour ce cas
  d'usage rare et interne.
