## Objectif

Standardiser l'envoi d'e-mails transactionnels sur le domaine de prod
`bati-axe.com`, avec expéditeur dynamique selon la nature du message :
`no-reply@bati-axe.com`, `notifications@bati-axe.com`, `contact@bati-axe.com`.
Couvre les parcours Pros, Particuliers, B2B et Alertes Admin.

## Prérequis bloquants avant activation prod

- DNS Cloudflare : TXT/CNAME DKIM, SPF (`v=spf1 include:amazonses.com ...`), DMARC sur `bati-axe.com`.
- Cloudflare Email Routing sur `contact@bati-axe.com` → Gmail admin.
- Variables d'env : `RESEND_API_KEY` (ou provider SMTP/SES), `NUXT_PUBLIC_SITE_URL=https://bati-axe.com`.

## Périmètre proposé

### 1. Moteur d'emailing multi-expéditeurs & templates
- `server/utils/email.ts` (existant, EML-01/Phase 6, P4) : ajouter les types d'expéditeurs `'no-reply'`, `'notifications'`, `'contact'`.
- Layout HTML responsive unique, branding copper/navy, footer légal LCEN.

### 2. Notifications Pros
- `server/api/v1/admin/verify.post.ts` : email validation / rejet (avec motif) de l'attestation décennale — `contact@`.
- `server/utils/notifyProLead.ts` : expéditeur `notifications@` (garde-fou idempotence `lead_notifications` déjà en place, à préserver).
- `server/api/v1/cron/decennale-alerts.get.ts` (nouveau) : alerte J-30 / J-7 avant expiration décennale.
- `server/api/v1/stripe/webhook.post.ts` : confirmation souscription/modification zone — **inclure la confirmation de retrait de zone effectif** (Subscription Schedule). Le mécanisme de transition a été vérifié fonctionnellement le 2026-08-29 (Test Clock Stripe, cf. `05.16-02-SUMMARY.md`) ; il ne manque que l'envoi de l'email à ce stade.

### 3. Notifications Particuliers
- `server/api/v1/projects.post.ts` : accusé de réception à la soumission du projet — `no-reply@`.
- `server/utils/handleLeadDecision.ts` : email quand un artisan débloque/prend en charge le lead — `contact@`.

### 4. Notifications B2B
- `server/api/v1/b2b/requests.post.ts` : accusé de dépôt de dossier à l'apporteur d'affaires — `contact@`.

### 5. Notifications Admin
- `server/utils/notifyAdmin.ts` (nouveau) : utilitaire centralisé vers `NUXT_ADMIN_EMAIL`, branché sur `claim.post.ts`, `projects.post.ts`, `b2b/requests.post.ts`.

## Vérification prévue

- Tests unitaires serveur (`npm run test:unit`) + mocks email en mode `EMAIL_LIVE=false`.
- Test d'envoi réel (`EMAIL_LIVE=true` + `RESEND_API_KEY`) sur chaque cas d'usage, contrôle anti-spam (DKIM/SPF).
- Test Cloudflare Email Routing : email externe vers `contact@bati-axe.com` → réception sur Gmail admin.
