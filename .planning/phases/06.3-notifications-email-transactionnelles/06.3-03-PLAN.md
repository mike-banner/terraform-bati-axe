<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → POST /api/v1/projects | Formulaire public : `customer_name`, `postal_code` etc. réinjectés dans des e-mails |
| Internet → POST /api/v1/b2b/requests | Formulaire public : champs contact réinjectés dans l'alerte équipe |
| e-mail sortant → boîte du particulier | Contient `access_token`, secret d'accès à l'espace projet |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-063-09 | Information Disclosure | projects.post.ts — `access_token` dans l'e-mail | mitigate | Envoyé uniquement à `data.customer_email` (l'adresse déposée), jamais loggé en prod : le bloc `console.log` du lien magique est supprimé par ce plan |
| T-063-10 | Information Disclosure | alerte admin projets | mitigate | L'alerte n'inclut ni téléphone ni e-mail du client (uniquement nom, zone, score) |
| T-063-11 | Spoofing | dépôt de projet avec l'e-mail d'un tiers → e-mail non sollicité | mitigate | Turnstile déjà en place sur le formulaire (`verifyTurnstile`) + CGU obligatoire ; e-mail purement transactionnel, avec `no-reply` et mention LCEN |
| T-063-12 | Elevation of Privilege | claim.patch.ts | mitigate | Aucune garde modifiée : 401 auth, 403 Premium, 403 décennale valide (05.15), 409 cap 3, 409 idempotence — l'e-mail est ajouté strictement après le claim réussi |
| T-063-13 | Denial of Service | envoi d'e-mail bloquant le POST | mitigate | Chaque envoi est dans un `try/catch` qui log et avale ; `notifyAdmin` est déjà non bloquant par construction |
