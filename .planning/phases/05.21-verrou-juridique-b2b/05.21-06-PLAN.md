- `GET /api/v1/tenders` → `{ tenders, zones, canClaim, frameworkSigned }` ; tender révélé (`status: 'claimed'`) : `engagement: { id, status, declared_amount_cents, confirmed_amount_cents, commission_cents, signed_at } | null`
- `POST /api/v1/engagements/pro/framework` `{ code? }` → `{ status: 'ALREADY_SIGNED' | 'OTP_SENT' | 'SIGNED', contract?: { html, sha256, version }, email_hint?, engagement_id?, signed_at? }`
- `POST /api/v1/tenders/:id/claim` `{ code? }` → 403 `data.data.code === 'FRAMEWORK_REQUIRED'` | `{ status: 'AMENDMENT_REQUIRED', contract, email_hint }` | `{ status: 'SUCCESS' | 'ALREADY_CLAIMED', tender }`
- `POST /api/v1/engagements/:id/declare-quote` `{ outcome: 'quote', amount }` | `{ outcome: 'not_awarded' }` → `{ status, declared_amount_cents, commission_cents }`
- `GET /api/v1/engagements/:id/document` → page HTML imprimable
Erreurs $fetch : message humain dans `err.data.statusMessage`, code métier dans `err.data.data.code`.
Contraintes de saisie (alignées sur Zod serveur) : code `^\d{6}$` ; montant : utiliser les constantes auto-importées de `app/utils/commissionTiers.ts` (plan 02) — `AMOUNT_INPUT_MAXLENGTH` (16 = `z.string().max(16)`) et `AMOUNT_INPUT_PATTERN` (≤ 9 chiffres entiers, décimales `,`/`.` 2 max, espaces y compris insécables autorisés, cohérence testée contre `parseAmountToCents` au plan 02).
Paliers de commission : `COMMISSION_RATE_LOW_PCT`, `COMMISSION_RATE_HIGH_PCT`, `COMMISSION_THRESHOLD_LABEL` (même fichier) — jamais 8 / 6 / 200 000 en dur dans un composant.
