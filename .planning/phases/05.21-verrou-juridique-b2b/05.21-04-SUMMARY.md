# Phase 05.21 Plan 04 : côté partenaire (convention par lien à jeton) Summary

Le partenaire signe sa convention sans compte (lien personnel + OTP) ; la diffusion est refusée (409) sans convention signée, la restitution aussi sauf dérogation admin tracée.

## Réalisé
- Soumission B2B : envoi non bloquant du lien de signature (`revokePrevious: false`) si aucune convention signée ; jeton jamais renvoyé dans la réponse.
- `GET /api/v1/b2b/engagement/:token` : convention + avenants (sans commission, sans coordonnées pro), en-têtes no-store/no-referrer/noindex, rate limit 30/10 min/IP, 404 uniforme.
- `POST /api/v1/b2b/engagement/:token/framework` : signature en 2 temps, audit, notification admin (uniquement à la première signature).
- `assertPartnerFrameworkSigned` (tests RED puis GREEN), gardes dans `diffuse` (aucune dérogation) et `restitution` (dérogation D-07 avec audit `framework_override` bloquant).
- `partner-link.post.ts` : renvoi admin avec rotation des jetons, motif framework / confirm_quote, 409 si rien à faire (vérifié avant émission).

## Deviations from Plan
- Notification admin conditionnée à `e.created` (évite un doublon sur rejeu idempotent) : ajout mineur.
- Dérogation restitution : l'audit dédié est inséré avant l'envoi (bloquant) et l'audit final existant porte aussi les métadonnées d'override (deux lignes `b2b_restitution_sent` en cas de dérogation).
- Signatures réelles de `signature.ts` conformes au plan ; colonne `type` (et non `engagement_type`) utilisée pour `b2b_engagements`.
